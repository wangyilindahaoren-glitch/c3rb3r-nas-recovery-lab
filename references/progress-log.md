# 进度记录：每轮开工落 `PROGRESS.md`，收尾结项

> 作者：wangyilin ｜ 首发：2026-11-03
> 配套脚本：`scripts/progress.py`（纯标准库，NAS 端 / 本地端都能跑）

---

## 1. 为什么必须有它

一次恢复动辄**几小时、跨多个会话、夹着几个 GB 的后台任务**：

- 雕刻扫描要跑 2~4 小时，跨天；
- 中间可能换人、换会话、换模型；
- 关键数字（多少个密文、多少个已装回、G 值是多少）一旦丢了，
  下一个人可能把整盘重扫一遍，或者把已经删过的密文再删一次。

所以规定：**每轮开工第一件事就是落一份 `PROGRESS.md`**，
之后每完成一个阶段就更新一次。它是**人可读**的（Markdown，直接给人看），
同时**机器可读**（元数据在 HTML 注释里，脚本能解析）。

> 第 14 步「收尾回写 skill」管的是**经验沉淀**（把新学到的东西写进 skill 的文档）；
> 本文件管的是**当前进度**（这一轮干到哪了）。两者互补，都不能省。

---

## 2. 文件放哪

`PROGRESS.md` 放在**工作目录**（不是 skill 目录）：

```
<工作目录>/
├── PROGRESS.md          ← 进度表（本文件）
├── targets.tsv          ← 目标清单
├── footers.json         ← orig_len 长度表
└── ...                  ← 其它中间产物
```

`scripts/progress.py` 默认写 `<工作目录>/PROGRESS.md`，
用 `--file` 可以指定别的路径（例如放在 NAS 上，或按目标分成多份）。

> ⚠️ `PROGRESS.md` **不要提交到公开仓库**（已在 `.gitignore` 里）。
> 它含目标路径、NAS 信息和真实数字。

## 3. 命令速查

```bash
P="python3 scripts/progress.py"

# ── 开工（第一件事）────────────────────────────────
$P --dir /work init \
    --target "用户A home 的 624 个密文" \
    --nas "群晖/DSM 7.2.1/14.5TiB RAID1" \
    --g 9324851 \
    --note "先走路线C，同步扫回收站" \
    --next "读 footers 拿 orig_len"

# ── 切阶段（每完成一步就切）────────────────────────
$P --dir /work stage --name "8 路线D 雕刻" --note "单路 nice 19"

# ── 记日志（任何有信息量的事）──────────────────────
$P --dir /work log "已盘出 624 个密文，mode 分布 484/99/41"

# ── 记关键数字（报告里要用的那些）──────────────────
$P --dir /work metric --name "已装回原件" --value 142
$P --dir /work metric --name "深度校验通过" --value 92

# ── 换会话/接手时先读回来 ─────────────────────────
$P --dir /work status

# ── 结项 ─────────────────────────────────────────
$P --dir /work close --result "救回 459/483，其余 24 个走路线C"
```

## 4. 什么时候写

| 时机 | 动作 | 为什么 |
|---|---|---|
| **开工第一件事** | `init` | 换会话/换人时，第一眼就知道这轮在干嘛 |
| **每完成一个阶段** | `stage` | 阶段清单能一眼看出卡在哪 |
| **拿到任何数字** | `metric` | 报告要用的数字当场记，别等收尾回忆 |
| **踩坑 / 发现异常** | `log` | 这些是第 14 步回写 skill 的素材 |
| **有后台长任务在跑** | `log` + 记下 PID/日志路径 | 换会话后能立刻找到那个任务 |
| **收尾** | `close` | 留一份"这轮到底救回多少"的凭据 |
| **下次开工** | 再 `init` | 自动开第 N 轮，阶段清单重置，历史日志保留 |

## 5. `PROGRESS.md` 长什么样

```markdown
<!-- c3r-progress-meta

started: 2026-11-03 20:46
updated: 2026-11-03 21:15
-->

# 恢复进度

## 目标

用户A home 的 624 个密文

## 环境

| 项 | 值 |
|---|---|
| NAS | 群晖/DSM 7.2.1/14.5TiB RAID1 |
| G 值 | 9324851 |

## 阶段

- [x] 0 分流与密钥窗口
- [x] 1 preflight 环境自检
...
- [-] 8 路线D 雕刻          ← 进行中
- [ ] 9 验证校验
...

## 关键数字

| 指标 | 值 |
|---|---|
| 已装回原件 | 142 |

## 下一步

扫完认领装回

## 日志

- [2026-11-03 20:46] 开工：先走路线C
- [2026-11-03 21:15] 进入阶段：8 路线D 雕刻（单路 nice 19）
```

**阶段三态**：`[x]` 已完成 ｜ `[-]` 进行中 ｜ `[ ]` 未开始。
`stage` 命令会自动把目标之前的阶段标 `[x]`、目标标 `[-]`、之后的保持 `[ ]`。

**元数据块**放在文件开头的 HTML 注释里：Markdown 渲染器看不见，
但脚本能解析，`status` 就靠它。

## 6. 「关键数字」记哪些

记**报告里要写、且丢了就重算不出来的**那些：

- 密文总数、按 mode 的分布
- `G` 值（重算要跑 `gens`，不便宜）
- `orig_len` 长度表在哪（`footers.json` 的路径）
- survey 各状态计数（`exact` / `no_candidate` / …）
- 雕刻扫描的进度（已扫 chunk / 总 chunk）
- 认领命中数、装回数、校验通过数
- **磁盘占用**：密文还剩多少、回收站里还有多少

**不要**记能随时重算的东西（文件总数、目录大小）。

## 7. 坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `init` 把上一轮的阶段全标成完成 | 老版本只追加不重置 | 本版 `init` **每轮重置阶段清单**，历史保留在日志里 |
| 进度文件里出现 `## ## 目标` | 标题常量带了 `## ` 前缀，拼的时候又加了一遍 | 标题常量统一**不带**前缀，只在写文件时加 |
| 元数据块跑到文件末尾 | 拆段时没先把 HTML 注释摘掉 | `split_sections` 先剥元数据再分段 |
| 进度表在 NAS 上被加密成了 `.L0CK3D` | 进度表也写在被勒索的共享里 | **`PROGRESS.md` 写在工作目录**，最好在 NAS 之外 |
| 进度表和真实文件混在一起被一起删了 | 收尾清理时没排除 | `tidy_delivery.py` 只处理恢复目录；进度表单独放、单独备份 |
| 后台任务在跑，进度表没记 PID | 只记了"在跑"没记"在哪" | `log` 时把**日志路径**和**PID**一起记进去 |

## 8. 和第 14 步的关系

| | 进度记录（本文件） | 第 14 步「收尾回写 skill」 |
|---|---|---|
| 记什么 | 这一轮**当前**干到哪、拿到多少 | 这一轮**新学到**什么经验 |
| 写到哪 | 工作目录的 `PROGRESS.md` | skill 的 `references/*.md` + `SKILL.md` 工具表 |
| 何时 | **全程持续**更新 | **收尾时**一次 |
| 丢了会怎样 | 这轮断了，接不上 | 学费白交，下一轮重复踩坑 |

**两条都要做。** 进度日志里 `log` 出来的"踩坑 / 异常"条目，
就是第 14 步回写 skill 的现成素材——收尾时照着日志往 `pitfalls.md` 里搬。

---

## 9. 给执行模型的提示

- **开工第一件事就是 `init`**，别等做完了才想起来记。
- 每切一个阶段就 `stage` 一次，不要攒到最后一次性补。
- 数字当场记（`metric`），不要靠回忆。
- 换会话时第一件事是 `status`，读完再动手。
- 收尾 `close`，然后**执行第 14 步**回写 skill。
